Integrations give your agents access to external tools and data. You connect an integration once, then approve the specific tools an agent needs before it runs.

<Info>
  You need a Dataleap account, access to `https://app.dataleap.ai`, and an account or credentials for the service you want to connect. Your workspace admin may restrict some integrations or tools.
</Info>

## Connect an integration

You can connect an integration while building an agent or from **Settings** > **Integrations**.

### Connect from settings

<Steps>
  <Step title="Open Integrations">
    Open `https://app.dataleap.ai`, open **Settings**, and select **Integrations**.
  </Step>

  <Step title="Choose where to save the connection">
    Select **Personal** for a connection that belongs to you. If you're in a team, you can select the team instead. Dataleap then asks **Whose account is this?**: choose **My own account** for your own login, or **A shared account** for a team or service login. See [Accounts in a team](/share/team-spaces#accounts-in-a-team).
  </Step>

  <Step title="Find the integration">
    Click **Add Integrations**, search for the integration, and select it. Review its description, available tools, available triggers, and any credit notice before connecting.
  </Step>

  <Step title="Start the connection">
    Click **Connect**. The setup screen depends on the integration:

    - OAuth integrations open an authorization window. Sign in to the provider, review the requested access, and approve it.
    - Some integrations ask for credentials or other configuration in a Dataleap dialog. Enter the requested details and submit the form.
    - Integrations that do not require authorization connect immediately.
  </Step>

  <Step title="Confirm the connection">
    Finish the provider or configuration screen and return to Dataleap. The integration appears in **Integrations**. If it is already connected, Dataleap may reuse the existing connection.
  </Step>
</Steps>

### Connect from an agent

When an agent needs an integration that is not connected, describe the task in the agent's chat. Dataleap identifies the integration it needs and shows a **Connect** action. Select it, complete the authorization or configuration screen, and return to the chat.

Connecting an integration to your account does not automatically give every agent access to every tool. The agent asks for access separately when it needs to use the connection.

## Use an integration

An integration's available actions depend on the integration, the connection type, your account's access, and your workspace's policies.

<Steps>
  <Step title="Describe what you want the agent to do">
    Ask the agent to use the integration. For example: *"Find the open Jira issues assigned to me and summarize the blockers."*
  </Step>

  <Step title="Review the requested tools">
    When the agent shows **Activate connections**, expand each integration to review the tools it wants to add or remove. Tool names and descriptions appear in the list. Some tools may use additional credits.
  </Step>

  <Step title="Approve access">
    Click **Approve All** to activate the requested connections and let the agent continue. The approval applies to that agent's workflow. Dataleap asks again if the agent later needs a different set of tools.
  </Step>
</Steps>

### Personal and team connections

- A **Personal** connection runs with the account you authorized. It's yours, and your personal agents use it.
- In a team, an account is either a **Shared account**, which any team member can use on the team's agents, or a **Personal account**: someone's own login added to the team. A team agent can use a Personal account only after its owner approves it for that agent. See [Accounts in a team](/share/team-spaces#accounts-in-a-team).
- If the same integration appears more than once, check the account and team labels before approving access. They may refer to different accounts or credentials.

## Which Slack connection to use

Slack is the one integration you can connect twice: once with your personal Slack account, and once org-wide on behalf of your whole organization. Both can show up under **Integrations**, and they have different capabilities.

| | Personal connection | Org-wide connection |
|---|---|---|
| Default for | your personal agents | agents in a team space |
| Runs as | you | the organization's Slack bot |
| Best for | searching messages, reading and writing private channels and DMs, acting as you | most day-to-day Slack work: sending and reading messages, managing channels, reacting |
| Can't do | — | search messages, or read private channels and DMs the bot hasn't been added to |

If your agent can't find or read a private channel or DM, it's probably using the org-wide connection. Ask it in the chat:

> *"Please switch from the org-wide Slack connection to my personal Slack connection."*

<Note>
  Your admin may have installed Slack without user permissions — in that case personal connections aren't available, and the org-wide connection is your only option.
</Note>

For more detail about workspace-wide integration and tool governance, see [Integrations & permissions](/admin/connected-apps-management).

## Disconnect and deauthorize an integration

Disconnect an integration when you no longer want Dataleap to use the connection. If the integration is used by agents, review the affected agents before confirming.

<Warning>
  Disconnecting removes the saved connection from Dataleap and removes that connection from the agents that use it. It does not delete the underlying records or data in the external app.
</Warning>

<Steps>
  <Step title="Open the connection list">
    Open **Settings** > **Integrations** and find the integration. Use **Search** if needed.
  </Step>

  <Step title="Open the disconnect dialog">
    Open the integration's actions menu and select **Disconnect**.
  </Step>

  <Step title="Review the impact">
    Review the account label, team information, and the list of agents that use the connection. If you added the account to a team, that team's agents lose it too.
  </Step>

  <Step title="Choose what happens to affected agents">
    **Deactivate affected agents** is selected by default. Leave it selected unless you have already replaced the connection and are ready to update the affected agents.

    Clear the option only if you intentionally want the agents to remain enabled while you replace or reconfigure their connection. An enabled agent without a usable connection may fail when it runs or may wait for a new connection.
  </Step>

  <Step title="Confirm the disconnect">
    Click **Disconnect Integration**. Dataleap removes the connection, removes its access from affected agents, and notifies those agents. If deactivation was selected, affected agents are also disabled.
  </Step>
</Steps>

For supported managed integrations, Dataleap also removes the managed provider connection. Some providers keep a separate authorization record. If the provider still lists Dataleap under **Authorized apps**, **Connected applications**, or a similar setting, remove Dataleap there to complete provider-side deauthorization.

Disconnecting a team's Shared account affects every team agent that depends on it. Coordinate with the team before removing it. To take your own account out of one team without disconnecting it, use **Remove from team** on the team's page instead.

## Delete your data

To remove Dataleap's access to an app and delete the data Dataleap received from it, follow these steps.

<Steps>
  <Step title="Disconnect the integration in Dataleap">
    Follow [Disconnect and deauthorize an integration](#disconnect-and-deauthorize-an-integration). Dataleap deletes the saved connection and its credentials, and your agents stop using the integration.
  </Step>

  <Step title="Remove Dataleap in the app's settings">
    In the app, remove Dataleap from its list of authorized or connected apps. This revokes Dataleap's access at the source and stops new data, such as new leads, from reaching Dataleap.

    For example, for Meta Ads, open Facebook and go to **Settings & privacy** > **Settings** > **Business integrations**, find **Dataleap**, and click **Remove**.
  </Step>

  <Step title="Ask us to delete data already collected">
    Disconnecting an integration or deleting an agent keeps your run history, including data that came from it, such as lead answers. To delete it, email [privacy@dataleap.ai](mailto:privacy@dataleap.ai) with your account email and organization name. We'll confirm when the deletion is done.
  </Step>
</Steps>

## Troubleshoot connection issues

| Problem | What to do |
|---|---|
| The integration does not appear in the list | Clear the search, check whether you are browsing **Personal** or a team, and confirm that your workspace admin has not restricted the integration. |
| The authorization window does not open | Allow popups for `https://app.dataleap.ai`, then select **Connect** again. |
| You closed the authorization window | Start the connection again and complete the provider flow before closing the window. |
| Dataleap says the credentials are invalid | Sign in to the intended provider account and verify the requested credentials or configuration. Then retry the connection. |
| The integration connected but is not listed | Reopen **Settings** > **Integrations** and refresh the page. If it is still missing, try connecting again. |
| A requested tool is unavailable | Expand the connection request to see which tools are unavailable. Your workspace admin may have blocked them, or the provider account may not grant the required access. |
| An agent cannot use a connection after it was disconnected | Connect or authorize the integration again, approve the requested tools in the agent, and re-enable the agent if it was deactivated. |
| A team connection or team option is missing | Confirm that you belong to the team and that your organization allows Team Connections. Contact your workspace admin if you need access. |
| The connection has expired or access was revoked | Follow the agent's **Reconnect** prompt and complete authorization again. If the provider still shows Dataleap as authorized, check the provider's authorized-app settings. |

If these steps do not resolve the issue, [contact Dataleap](https://www.dataleap.ai/contact-us) and include the integration name, the step that failed, and the exact error message. Do not include passwords, access tokens, or other secrets.
