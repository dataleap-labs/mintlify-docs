title: "Store data between runs"
description: "Every agent has a database of its own. Ask your agent to keep what matters, then open, search, and export the tables yourself."

Every agent has a database of its own. When your agent saves something there, it is still there on the next run — hours or weeks later — so an agent can add up totals over time, remember what it has already handled, and build on its own earlier work.

You don't switch this on and there is nothing to set up. Ask your agent to keep track of something, and it saves it.

## Knowledge and the database are different things

|                  | What it holds                                         | Who puts it there |
| ---------------- | ----------------------------------------------------- | ----------------- |
| **Knowledge**    | Reference files you upload for your agent to read     | You               |
| **Database**     | Rows your agent writes down as it works               | Your agent        |

[Knowledge](/build/add-knowledge) is what you give your agent to read. The database is what your agent writes down for itself.

## Ask your agent to keep something

Say what should be remembered and why. Your agent works out the tables it needs.

- "Keep a record of every invoice you process, so you never process the same one twice."
- "Track the weekly totals you report, so you can show me the trend later."
- "Remember which candidates you have already contacted."

Your agent reads that data back on later runs, which is what makes "compare this week against the last four weeks" a question it can actually answer.

## Open the data yourself

<Steps>
  <Step title="Open the Database tab">
    On the agent, open the **Database** tab. It lists the tables your agent has saved under **Tables saved by this agent**, each with a row count.

    If you see **No database yet**, your agent hasn't stored anything — it creates its database the first time it saves data.
  </Step>
  <Step title="Click View data">
    **View data** opens the database on its own page in a new browser tab.
  </Step>
  <Step title="Pick a table and read it">
    Choose a table from **Tables** on the left. Click any column heading to sort by it, and use **Previous** and **Next** to move through the rows.
  </Step>
</Steps>

## Search every row

The search box above the table searches the whole table, not just the page you are looking at. It matches your text against every column, so you can find a row by an order number, a name, or anything else it contains.

## Export a table

Click **Export**, then choose **Export as CSV** or **Export as Excel**.

The file matches what you are looking at. If a search is active you get only the matching rows, sorted the way you sorted them on screen. A single export is capped at 32 MiB — for a very large table, choose CSV, which is the smaller format.

## What you can't do in the viewer

The page is marked **Read only**, and that is the whole story: you can read, sort, search, and download, but you can't add, edit, or delete a row there. To correct or clear out what's stored, ask your agent to do it.

## Who can see it

Access follows the agent. Anyone who can view the agent can open its database, and nobody else can — the page asks them to sign in first. [Use-only](/share/use-only) access to an agent is not enough to open its database.

## Before you rely on it

| If you                                        | What happens to the data                                                                          |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Restore an earlier version of the agent        | Nothing. Restoring covers your agent's setup and files; its database is not rolled back with them. |
| Copy the agent, or use it as a template        | The new agent starts with an empty database of its own. Nothing is copied across.                  |
| Archive the agent                              | The database closes straight away and nobody can open it.                                          |

<Warning>
  An archived agent's database is deleted 10 days after you archive it, and un-archiving after that does not bring the data back. Export anything you want to keep before you archive an agent.
</Warning>
