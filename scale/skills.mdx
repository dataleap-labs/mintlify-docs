## What makes a good skill

| Good skill | Example |
|---|---|
| **Encode knowledge** | Your Ideal Customer Profile — every agent qualifies leads the same way. |
| **Standardize a methodology** | Your internal pricing methodology — defined once, applied identically by every agent that prices anything. |
| **Define your data** | What each metric or field means, and what it's called in your systems — shared analytics language. |
| **Standardize outputs** | How a report should be structured and worded. |
| **Lock the design** | The look for documents and dashboards — always on-brand. |

The signal that something should be a skill: you catch yourself typing the same definition or procedure into a second agent — "wait, I'm redoing this work."

## Create a skill

Two ways — out of an agent you already built, or from scratch:

<Tabs>
<Tab title="From an agent's chat">

You built an agent and notice one part of it is reusable — just tell Dataleap: *"Create a skill out of the scoring logic for new candidates."* It drafts the skill from what you built, proposes name, description, and content, and saves once you confirm.

Which agent you use decides who else gets it. Create a skill through a personal agent and it stays private to you. Create one through a [team agent](/share/team-spaces) and it is still yours, but it is shared with that agent's team as **Can edit** in the same step — so the agent can use it from your next message, and a teammate can ask that same agent to refine it.

Click **Add Skill** and pick how: **Create in Chat**, **Create Manually**, or **Import Skill** (if the standard already exists as a file).

<Tip>
  A skill's instructions can be up to 256 KB, but that is far more than you want: every rule in a skill costs tokens on every run that loads it. Keep the instructions as lean as they can be while still doing the job, and move long reference material into a [bundled file](#bundled-files) the agent only reads when it needs it.
</Tip>

## Import and export skills

A skill doesn't have to start in Dataleap, and it doesn't have to stay there. Bring one in from a file, or take one out as a file — so a standard you already wrote somewhere else moves across without retyping.

### Import a skill

In the **Skills** section, click **Add Skill** and choose **Import Skill**. Drag a file onto the dialog, or click **Browse files**. Dataleap takes `.md`, `.zip`, and `.skill` files up to 30 MB — including an Agent Skills ZIP exported from another platform.

Nothing is saved yet. **Review Skill Import** shows what was found in the file — **Name**, **Description**, **Bundled Files**, and the **Instructions** — and lets you fix the name or description before anything is created. Skill names have to be unique, so if you already have one with that name, rename it here. Click **Import Skill** to save, or **Cancel** to drop it.

These limits apply to what you upload:

| Limit | Maximum |
|---|---|
| Upload size | 30 MB, both as sent and unpacked |
| Files in one bundle | 100, counting the skill's own instructions file |
| Any single bundled file | 25 MB |
| The skill's instructions | 256 KB |

Go over one and the upload is refused with a message naming the limit, so nothing half-imports.

### Export a skill

Open the skill, open its actions menu, and choose **Export**. You get a ZIP of the skill — its instructions and any bundled files — to archive, hand to someone outside your team, or load into another tool that reads the Agent Skills format.

### Replace a skill's contents

When a skill's source of truth lives outside Dataleap, you don't have to delete it and import a new copy. Open the skill's actions menu, choose **Replace Contents**, and upload the new file. You get the same review step first, and you need edit access to the skill.

<Warning>
  Replacing is a swap, not a merge: the upload becomes the skill's entire contents, and bundled files that aren't in the upload are removed. The review step lists exactly which files would go. Use **Export** first if you want a backup.
</Warning>

## Bundled files

A skill can carry files alongside its instructions, which keeps the instructions themselves short. They're listed under **Bundled Files** on the skill's page, each with its path and size. The agent groups them into three folders:

| Folder | What belongs there |
|---|---|
| `scripts/` | Helpers the agent runs instead of working the same logic out again. |
| `references/` | Longer documentation the agent reads only when it needs it. |
| `assets/` | Templates and files the workflow uses. |

On the skill's page you can download any bundled file, and edit the markdown ones in place if you have edit access. Other text files open read-only, and anything else is download-only.

### Add or change bundled files from chat

You can't add or remove a file from the skill's page — that happens in chat. Ask the agent that owns the skill:

> "Add this report template to the *Pricing Methodology* skill, and point the instructions at it."

The agent stages the files, then shows you the name, description, the full instructions, and the resulting list of bundled files, and waits for you to approve before saving.

<Warning>
  Read that file list before you approve. The set you approve becomes the skill's bundled files, so a file missing from the list is a file the skill loses.
</Warning>

## Use a skill

Agents don't guess which skills to use — you tell them. When building or refining an agent, reference the skill explicitly:

> "When it comes to pricing, use the *Pricing Methodology* skill."

From then on, that step of the workflow runs on the skill's definition. And when the methodology changes, you update the skill once — every agent using it follows.

<Note>
  Be proactive: Dataleap won't suggest skills on its own. Spotting the reusable part is your job; packaging and reusing it is one sentence.
</Note>

## Share a skill

Skills have three levels of reach:

- **Personal** — your own skills, visible only to you.
- **Team** — share a skill into a [team space](/share/team-spaces) (it has its own **Skills** tab); every teammate's agents can use it.
- **Org-wide** — publish it for the whole company. The classic case: company-wide metric definitions, so every agent anyone builds speaks the same data language.

Skills you create in the **Skills** section start private. A skill you create through a team agent starts shared: it is listed under **Your Skills** as **Shared**, with that team set to **Can edit**. You stay the owner — to change that, open the skill's actions menu, choose **Share**, and set the team to **Can view and use** or remove it.
