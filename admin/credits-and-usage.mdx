Every agent run consumes credits. Dataleap gives you the visibility to see where they go, the controls to cap them, and — most importantly — the levers to need fewer of them.

## Chat costs vs. run costs

Your costs come from two places, and they behave differently:

- **Chat costs** — what you spend talking to Dataleap while building and refining an agent. High chat costs at the start are normal: that's the building phase. Once the agent is finished, they drop to zero.
- **Run costs** — what each execution consumes. This is the recurring cost, and it's where the optimization levers below apply.

## Budgets (admin)

The **Budgets** page in the admin panel shows the monthly org spend for the billing period — and sets the caps:

- **Weekly member budgets** — hard weekly caps per person, resolved in order: **user-specific budget → team budget → org default**. The most specific one wins.
- **Weekly team-agent budgets** — a hard weekly budget **shared across every team agent on a team**, with an org default as fallback.
- **Monthly org budgets** (token and Dataleap usage) are monitoring views — passing them doesn't block runs or stop agents; the weekly caps are the hard limits.

## Analytics (admin)

The **Analytics** page answers "what's actually happening":

- **Overview** — users, agents, active agents, weekly active users, and the billing period's cost split (token, Dataleap, and tool usage).
- **Adoption** — how agent count and weekly active users develop over time.
- **Per-agent list** — every agent with its owner (person or team), active status, cost breakdown, and run count. Expand any agent for an **AI-generated summary of what it does** — no more guessing what "New Workflow" is.

## Export cost and usage (admin)

Your organization's cost and usage figures can also leave Dataleap — into a finance tool, a data warehouse, a scheduled reporting job, or an agent that reports on spend. You get them with an API key from **Workspace Settings** > **API Keys**. The same kind of key can also feed [App Activity](/admin/connected-apps-management#app-activity) into a security tool.

<Info>
  **API Keys** is only available to admins in organizations on an Enterprise plan, including an Enterprise trial. Other members and plans don't see it.
</Info>

### Create a key

<Steps>
  <Step title="Start a new key">
    Open **Workspace Settings** from your profile menu, choose **API Keys** under **Controls**, and click **Create key**.
  </Step>
  <Step title="Name it and choose its scopes">
    Give the key a **Name** that identifies its owner, such as the tool or team that will use it. Under **Scopes**, tick at least one. A key can carry both.

    | Scope | What the key can read |
    |---|---|
    | **Cost and usage · Read** | Your organization's cost and usage data. |
    | **App activity · Read** | The [App Activity](/admin/connected-apps-management#app-activity) record, for a security tool such as a SIEM. It never includes a tool's input or output. |
  </Step>
  <Step title="Set an expiry">
    Under **Expiration**, pick **Never**, **30 days**, **90 days**, **1 year**, or **Custom** to choose a date. A key with an expiry stops working at the end of that day. A key set to **Never** keeps working until you revoke it.
  </Step>
  <Step title="Copy the key">
    Click **Create key**, then copy the key before you click **Done**. Dataleap shows it only once. If you lose it, create a new key and revoke the old one.
  </Step>
</Steps>

<Frame caption="The Create an API key dialog with both scopes ticked.">
  <img src="/images/admin-create-api-key.svg" width="496" alt="The Create an API key dialog with a Name field, the Cost and usage · Read and App activity · Read scopes both ticked, Expiration set to Never, and Cancel and Create key buttons" />

<Warning>
  Treat the key like a password. Anyone who has it can read whatever its scopes allow, including member names and email addresses.
</Warning>

### What the key can read

With **Cost and usage · Read**, the key reads a daily report of your organization's usage and cost, for up to 31 days at a time. You can see organization totals, or break the figures down by member or by team, and further by agent and by model.

Each row shows token usage, charged tool calls, and the cost in your organization's currency, split into model, Dataleap, and tool cost. The cost is consumption only: it leaves out platform fees, budgets, allowances, taxes, and invoice adjustments.

With **App activity · Read**, the key reads the same tool calls you see on the **App Activity** page, up to 31 days at a time: who caused each call, which agent, app, and tool were involved, when it ran, and whether it succeeded. Each event links back to that event on the **App Activity** page. The key never reads what a tool was sent or what it returned.

### Let an agent use the key

Every active key comes with ready-made agent instructions. They explain how to request the data for each of the key's scopes and what each figure means. Paste them into an agent's chat so it knows how to use the key.

You can copy them in four places: under **Setting up an agent?** right after you create the key, with the copy icon on the key's row, with **Copy agent instructions** in the row's actions menu, or with **Copy instructions** in the key's details.

The instructions don't contain your key — only a placeholder where the key goes. Don't paste the key into the chat. When the agent needs it, it gives you a form to enter it in.

The instructions can be copied only while the key is active.

### Keep track of keys and revoke them

The **API Keys** list shows each key's name and the start of the key, its **Scopes**, who created it and when, when it was **Last used**, and its **Status**: **Active**, **Expires soon** (within seven days), **Expired**, or **Revoked**. Expired and revoked keys sit in a separate **Inactive keys** group below the active ones, which you can collapse.

Click a key to open its details: when it expires, what each of its scopes allows, and its agent instructions.

To revoke a key, choose **Revoke** in its row's actions menu or at the bottom of its details, and confirm with **Revoke key**. Revoking is permanent, and any job that uses the key stops working. The key moves to **Inactive keys** as **Revoked**.

## Your own usage

Outside the admin panel, everyone sees their own picture: **Usage** in the sidebar shows your weekly credit usage and which agents consume it, and each agent's **Runs** panel lists every execution with status, output, duration, and cost.

## Reduce the spend: the levers that matter

| Lever | Effect |
|---|---|
| [Event triggers instead of frequent polling](/build/triggers) | Agents run only when there's real work — ~100x cheaper than tight schedules. |
| [Programmatic tool calling](/scale/programmatic-tool-calling) | Deterministic workflows use far fewer credits — 30–80% reduction. |
| [Model tiers](/scale/sub-agents-and-intelligence-levels#model-tiers) | Pro or Expert to build, Basic to run; move up only when runs struggle — a higher tier can cost 3–4x more. |
| Optimized instructions | Clear instructions reduce iterations per run — fewer loops, fewer credits. |
| Pre-filter at the source | Filter in the source system (e.g., a Snowflake view or an email filter) so the agent reads less data. |
